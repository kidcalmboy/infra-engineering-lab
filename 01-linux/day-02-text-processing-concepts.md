## 1. 표준 입력과 표준 출력

### 한 줄 정의

Linux 명령어는 데이터를 **입력받아 처리하고 결과를 출력하는 작은 도구**로 생각할 수 있다.

일반적인 흐름:

```text
Standard Input
      ↓
   Command
      ↓
Standard Output
```

예를 들어:

```bash
cat server.log
```

은 파일을 읽고 그 내용을 터미널의 표준 출력으로 보낸다.

이 구조를 이해하면 여러 명령을 조합하는 이유가 명확해진다.

---

## 2. 파이프 `|`

### 한 줄 정의

파이프는 **왼쪽 명령의 표준 출력을 오른쪽 명령의 표준 입력으로 연결**한다.

```bash
history | grep "cd"
```

흐름:

```text
history 실행 결과
      ↓
     |
      ↓
grep이 입력으로 받음
      ↓
cd가 포함된 줄만 출력
```

### `|`와 리다이렉션 차이

| 기호 | 역할 |
|---|---|
| `|` | 명령어의 출력 → 다른 명령어의 입력 |
| `>` | 명령어의 출력 → 파일, 기존 내용 덮어쓰기 |
| `>>` | 명령어의 출력 → 파일 끝에 추가 |

즉 파이프는 **명령과 명령을 연결**하고, 리다이렉션은 주로 **출력 목적지를 파일로 변경**한다.

---

## 3. 텍스트 처리 단계

로그 분석에서는 보통 다음 흐름을 사용한다.

```text
1. 필요한 줄 선택
2. 필요한 필드 추출
3. 같은 값끼리 정렬
4. 개수 집계
5. 우선순위에 맞게 재정렬
```

예:

```bash
grep "ERROR" problem03.log | cut -d ':' -f 1 | sort | uniq -c | sort -nr
```

각 단계:

```text
grep      → ERROR 줄만 남김
cut       → 서버 이름만 남김
sort      → 같은 서버끼리 붙임
uniq -c   → 서버별 발생 횟수 계산
sort -nr  → 발생 횟수가 많은 서버부터 출력
```

긴 명령어 하나가 아니라 **작은 도구 여러 개가 각자 한 가지 역할을 수행한다**고 이해하면 된다.

---

## 4. 명령어별 역할

### `grep` - 줄 단위 필터

```bash
grep "ERROR" server.log
```

파일 전체를 구조적으로 분석하는 것이 아니라 조건에 맞는 **줄**을 선택한다.

### `cut` - 단순 필드 추출

```bash
cut -d ':' -f 1 problem03.log
```

구조가 일정한 텍스트에서 특정 필드만 빠르게 뽑을 때 유용하다.

### `sort` - 정렬

```bash
sort
```

보기 좋게 만드는 용도뿐 아니라 `uniq`가 같은 값을 하나의 연속 그룹으로 인식하도록 데이터를 정리하는 역할도 한다.

### `uniq` - 연속 중복 처리

```bash
uniq -c
```

입력에서 서로 붙어 있는 동일 값을 묶고 개수를 센다.

### `awk` - 필드 기반 처리 언어

```bash
awk '$4 >= 400 {print $1, $3}' access.log
```

단순 추출뿐 아니라 조건 비교와 계산이 필요할 때 적합하다.

---

## 5. 파이프라인 해석 방법

다음 명령을 처음부터 통째로 외우지 않는다.

```bash
grep "ERROR" problem03.log | cut -d ':' -f 1 | sort | uniq -c | sort -nr
```

왼쪽부터 하나씩 실행한다.

### 1단계

```bash
grep "ERROR" problem03.log
```

ERROR 줄이 정확히 추출되는지 확인한다.

### 2단계

```bash
grep "ERROR" problem03.log | cut -d ':' -f 1
```

서버 이름만 나오는지 확인한다.

### 3단계

```bash
grep "ERROR" problem03.log | cut -d ':' -f 1 | sort
```

같은 서버가 붙어 있는지 확인한다.

이후 `uniq -c`, `sort -nr`을 붙인다.

### 실무에서 중요한 이유

한 번에 긴 명령을 실행하면 어느 단계가 잘못됐는지 파악하기 어렵다. 장애 분석에서도 **중간 결과 검증**이 중요하다.

---

## 6. ⚠️ 헷갈리기 쉬운 부분

### 파이프는 파일을 만드는 기능인가?

아니다. 파이프는 프로세스 사이의 데이터 흐름을 연결한다.

파일에 저장하려면 리다이렉션을 사용한다.

```bash
grep "ERROR" server.log > error.log
```

### `uniq -c`만 실행하면 전체 중복을 정확히 집계하는가?

입력이 이미 같은 값끼리 연속되어 있지 않다면 정확하지 않을 수 있다.

따라서 일반적인 집계에서는:

```bash
sort | uniq -c
```

형태가 중요하다.

### 명령어 순서는 아무렇게나 바꿔도 되는가?

아니다. 각 단계의 출력 형태가 다음 단계의 입력이 되므로 **순서가 의미를 만든다.**

---

## 7. 💼 실무 포인트

서버 운영에서 로그 분석 명령은 데이터가 달라지면 계속 변한다. 따라서 특정 명령 문자열을 암기하는 것보다 다음 질문을 먼저 생각한다.

```text
무슨 줄이 필요한가?
→ grep

무슨 값만 필요한가?
→ cut / awk

같은 값을 묶어야 하는가?
→ sort

몇 번 나왔는가?
→ uniq -c / awk

우선순위를 정렬해야 하는가?
→ sort -nr
```

이 관점이 있으면 새로운 로그 형식에도 대응하기 쉽다.

---

## 8. ✅ 핵심 정리

- Linux 명령어는 입력을 받아 처리하고 출력을 만드는 작은 도구로 볼 수 있다.
- 파이프 `|`는 왼쪽 명령의 표준 출력을 오른쪽 명령의 표준 입력으로 전달한다.
- `grep`은 줄 필터링, `cut`은 단순 필드 추출, `sort`는 정렬, `uniq`는 연속 중복 처리, `awk`는 필드 기반 조건·계산에 적합하다.
- 긴 파이프라인은 왼쪽부터 단계별로 실행해 중간 결과를 확인한다.
- 로그 분석에서는 **필터링 → 추출 → 정렬 → 집계 → 우선순위 정렬** 흐름을 자주 사용한다.
