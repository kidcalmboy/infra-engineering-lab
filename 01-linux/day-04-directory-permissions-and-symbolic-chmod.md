## ⚡ 명령어 빠른 복습

| 명령어 | 의미 | 언제 사용하는가 |
|---|---|---|
| `ls -ld directory` | 디렉터리 자체 권한 확인 | 디렉터리 접근 문제 점검 |
| `chmod 755 directory` | 디렉터리 권한을 `rwxr-xr-x`로 설정 | Owner 전체 권한, 나머지는 조회·접근 허용 |
| `chmod u+x file` | Owner에게 실행 권한 추가 | 기존 권한은 유지하고 `x`만 추가 |
| `chmod g-w directory` | Group의 쓰기 권한 제거 | 그룹의 생성·삭제·이름 변경 권한 제한 |
| `chmod o-r file` | Others의 읽기 권한 제거 | 다른 사용자의 파일 읽기 제한 |
| `chmod a+r file` | 모든 범주에 읽기 권한 추가 | Owner/Group/Others 모두 읽기 허용 |

### 문자 방식 `chmod` 기호

| 기호 | 의미 |
|---|---|
| `u` | user, 파일의 Owner |
| `g` | group, 파일에 연결된 Group |
| `o` | others |
| `a` | all, Owner + Group + Others |
| `+` | 권한 추가 |
| `-` | 권한 제거 |
| `=` | 지정한 권한으로 정확히 설정 |

## 1. 파일과 디렉터리의 권한 차이

### 한 줄 정의

`r`, `w`, `x`라는 표시는 같지만 **파일과 디렉터리에서는 실제 의미가 다르다.**

### 상세 설명

파일은 데이터 자체에 대한 권한을 의미하지만, 디렉터리는 내부의 이름 목록과 경로 접근, 항목 생성·삭제를 제어한다.

| 권한 | 파일에서의 의미 | 디렉터리에서의 의미 |
|---|---|---|
| `r` | 파일 내용 읽기 | 디렉터리 안의 파일 이름 목록 보기 |
| `w` | 파일 내용 수정 | 내부 파일/디렉터리 생성·삭제·이름 변경 |
| `x` | 파일 실행 | 디렉터리 진입 및 내부 경로 접근 |

### 실무에서 중요한 이유

`Permission denied`가 발생했을 때 대상 파일의 권한만 보면 원인을 놓칠 수 있다. 파일까지 도달하려면 경로에 포함된 디렉터리에도 적절한 `x` 권한이 필요하기 때문이다.

---

## 2. 디렉터리의 `r`, `w`, `x`

### 디렉터리의 `r` - 목록 조회

`r`은 **read**다.

디렉터리에서는 내부 항목의 이름 목록을 조회하는 권한과 연결된다.

```bash
ls directory
```

디렉터리에 `r` 권한이 있으면 어떤 파일 이름들이 있는지 목록을 확인할 수 있다.

> `r`은 디렉터리 내부의 생성·삭제·이름 변경 권한이 아니다. 그 역할은 `w`가 담당한다.

### 디렉터리의 `w` - 내부 항목 변경

`w`는 **write**다.

디렉터리에서는 내부의 디렉터리 엔트리를 변경할 수 있는 권한과 연결된다.

예:

```bash
touch directory/new.txt
rm directory/old.txt
mv directory/a.txt directory/b.txt
```

따라서 디렉터리의 `w` 권한은 다음 작업과 관련된다.

```text
파일 생성
파일 삭제
파일 이름 변경
하위 디렉터리 생성/삭제
```

### 디렉터리의 `x` - 경로 접근

`x`는 파일에서는 execute지만, 디렉터리에서는 **search/traverse 권한**으로 이해하는 것이 더 정확하다.

```bash
cd directory
```

또는:

```bash
cat directory/file.txt
```

처럼 디렉터리를 통과해서 내부 항목에 접근하려면 해당 디렉터리에 `x` 권한이 필요하다.

즉 디렉터리에서 `x`가 없으면 경로 자체를 따라 들어갈 수 없기 때문에 `Permission denied`가 발생할 수 있다.

---

## 3. 문자 방식 `chmod`

### 한 줄 정의

문자 방식 `chmod`는 기존 권한 전체를 다시 지정하지 않고 **특정 범주의 특정 권한만 추가·제거·설정**할 때 유용하다.

기본 구조:

```text
chmod [대상][연산자][권한] 파일또는디렉터리
```

예:

```bash
chmod u+x file.txt
```

의미:

```text
u → Owner
+ → 추가
x → 실행 권한
```

즉 Owner에게 실행 권한만 추가한다.

다른 예:

```bash
chmod g-w directory
```

Group의 쓰기 권한만 제거한다.

```bash
chmod o-r file.txt
```

Others의 읽기 권한만 제거한다.

### `=` 사용

```bash
chmod g=rx directory
```

Group 권한을 정확히 `r-x`로 설정한다. 기존 Group 권한은 지정한 값으로 대체된다.

---

## 4. 숫자 방식 vs 문자 방식

| 구분 | 숫자 방식 | 문자 방식 |
|---|---|---|
| 예 | `chmod 750 directory` | `chmod g-w directory` |
| 특징 | 전체 권한을 한 번에 설정 | 필요한 권한만 선택적으로 변경 |
| 장점 | 최종 권한 상태가 명확 | 기존 권한을 유지하면서 일부만 변경 가능 |
| 주의점 | 기존 권한을 통째로 덮어씀 | 현재 권한을 먼저 확인해야 변경 결과를 정확히 예상 가능 |

핵심 결론:

> 최종 권한을 명확히 지정할 때는 숫자 방식이 편하고, 기존 상태를 유지하면서 일부 권한만 조정할 때는 문자 방식이 유용하다.

## 5. 🧪 실습

### 실습 목표

파일과 디렉터리에 문자 방식 `chmod`를 적용하고, 디렉터리 권한의 의미를 직접 확인한다.

### 1. 디렉터리 생성

```bash
cd ~/linux-test
mkdir permission-dir
touch permission-dir/file1.txt
ls -ld permission-dir
```

### 2. 숫자 방식으로 디렉터리 권한 변경

```bash
chmod 700 permission-dir
ls -ld permission-dir
```

예상:

```text
drwx------
```

다시:

```bash
chmod 755 permission-dir
ls -ld permission-dir
```

예상:

```text
drwxr-xr-x
```

### 3. Owner에게 실행 권한 추가

실습 문제 정답:

```bash
chmod u+x file.txt
```

`u+x`는 Owner에게 `x` 권한만 추가한다.

### 4. Group의 쓰기 권한 제거

실습 문제 정답:

```bash
chmod g-w directory
```

`g-w`는 Group의 `w` 권한만 제거한다.

## 6. ⚠️ 헷갈리기 쉬운 부분

### 디렉터리의 `r`은 생성·삭제 권한인가?

아니다.

처음에는 디렉터리의 `r`이 이동, 변경, 삭제, 생성과 관련된 권한이라고 생각하기 쉬우나 실제로는 다음과 같다.

```text
r → 내부 이름 목록 조회
w → 내부 항목 생성·삭제·이름 변경
x → 디렉터리 진입 및 내부 경로 접근
```

> ⚠️ `cd`가 안 되는 문제는 `r`이 아니라 `x` 권한 부족 때문에 발생할 수 있다.

### `chmod`는 파일에만 사용하는가?

아니다.

`chmod`는 **파일과 디렉터리 모두에 사용한다.**

```bash
chmod 640 file.txt
chmod 750 directory
```

다만 같은 `rwx`라도 파일과 디렉터리에서 의미가 다르므로 대상을 기준으로 해석해야 한다.

### 디렉터리에 `x`만 있으면 목록을 볼 수 있는가?

일반적으로 `x`는 경로 접근 권한이고 `r`은 목록 조회 권한이다. 따라서 내부 파일 이름을 모르는 상태에서 자유롭게 목록을 확인하려면 `r`도 필요하다.

반대로 파일 이름과 경로를 이미 정확히 알고 있고 다른 조건이 충족된다면 `x` 권한만으로 해당 경로를 따라 접근할 수 있는 경우가 있다.

## 7. 🔧 Troubleshooting

### 문제

디렉터리 권한이 다음과 같았다.

```text
drw-r--r--
```

사용자가 다음 명령을 실행했다.

```bash
cd shared
```

결과:

```text
Permission denied
```

### 원인

디렉터리에 `x` 권한이 없다.

디렉터리에서 `x`는 파일 실행이 아니라 **디렉터리 진입과 경로 탐색 권한**을 의미한다.

따라서 `r`이 있어 내부 이름 목록과 관련된 권한이 있더라도 `x`가 없으면 `cd`로 정상 진입할 수 없다.

### 확인 방법

```bash
ls -ld shared
```

현재 사용자와 그룹도 함께 확인할 수 있다.

```bash
id
```

### 해결 방법

실제 요구사항에 맞는 범주에 `x` 권한을 추가한다.

예를 들어 Owner에게만 필요한 경우:

```bash
chmod u+x shared
```

모든 사용자에게 필요한 경우에는 권한 요구사항을 먼저 검토한 뒤 숫자 또는 문자 방식으로 필요한 범위만 부여한다.

### 검증

```bash
ls -ld shared
cd shared
pwd
```

### 배운 점

`Permission denied`가 발생했다고 무조건 `chmod 777`을 적용하는 것은 해결 방법이 아니다.

먼저 **어떤 사용자에게 어떤 작업이 필요한지**, 그리고 파일인지 디렉터리인지 확인한 뒤 부족한 권한만 조정해야 한다.

## 8. 💼 실무 포인트

서버에서 경로 접근 문제를 분석할 때는 최종 파일 하나만 확인하지 않는다.

예를 들어:

```text
/var/www/app/config.conf
```

파일에 접근해야 한다면 `/var`, `/var/www`, `/var/www/app` 같은 상위 디렉터리를 통과해야 한다. 따라서 경로 구성 요소의 디렉터리 `x` 권한도 함께 확인해야 한다.

운영 시 기본 점검 흐름:

```text
증상 확인
→ 현재 사용자/그룹 확인
→ 대상 파일 권한 확인
→ 상위 디렉터리 권한 확인
→ 필요한 권한 판단
→ 최소한의 권한만 변경
→ 재검증
```

또한 파일 삭제 문제에서는 대상 파일 자체의 `w`만 보지 말고 **부모 디렉터리의 `w`와 `x` 권한**도 확인해야 한다.

## 9. ✅ 핵심 정리

- `chmod`는 **파일과 디렉터리 모두**에 사용할 수 있다.
- 파일의 `r/w/x`와 디렉터리의 `r/w/x`는 의미가 다르다.
- 디렉터리 `r` = 내부 이름 목록 조회.
- 디렉터리 `w` = 내부 항목 생성·삭제·이름 변경.
- 디렉터리 `x` = 디렉터리 진입 및 내부 경로 접근.
- `chmod u+x file`은 Owner에게 실행 권한만 추가한다.
- `chmod g-w directory`는 Group의 쓰기 권한만 제거한다.
- 숫자 방식은 전체 권한 설정, 문자 방식은 일부 권한 조정에 유용하다.
- `Permission denied`가 나오면 파일뿐 아니라 상위 디렉터리 권한도 확인해야 한다.
- 권한 문제를 `777`로 해결하려 하지 말고 필요한 권한만 최소한으로 부여한다.
