## ⚡ 명령어 빠른 복습

| 명령어 | 의미 | 언제 사용하는가 |
|---|---|---|
| `ls -l file` | 파일 상세 정보 확인 | 권한·소유자·그룹 확인 |
| `ls -ld directory` | 디렉터리 자체 상세 정보 확인 | 디렉터리 권한 확인 |
| `chmod 640 file` | 권한을 `rw-r-----`로 설정 | 소유자/그룹/기타 권한 조정 |
| `chmod 644 file` | 권한을 `rw-r--r--`로 설정 | 일반 설정 파일 등에서 자주 확인 |
| `chmod 755 file` | 권한을 `rwxr-xr-x`로 설정 | 실행 파일·스크립트 등에 사용 가능 |

### `ls` 옵션

| 옵션 | 의미 |
|---|---|
| `-l` | **long format**. 권한, 소유자, 그룹, 크기, 수정 시간 등을 상세 출력 |
| `-d` | 디렉터리 내부 목록이 아니라 **디렉터리 자체**를 대상으로 출력 |

## 1. Linux 파일 권한이 필요한 이유

### 한 줄 정의

Linux 파일 권한은 **어떤 사용자가 파일에 어떤 작업을 할 수 있는지 제어하는 접근 제어 기능**이다.

### 상세 설명

Linux는 여러 사용자가 동시에 사용할 수 있는 운영체제다. 모든 사용자가 모든 파일을 읽고 수정할 수 있다면 설정 파일, 서비스 파일, 사용자 데이터가 쉽게 손상될 수 있다.

그래서 파일과 디렉터리마다 다음 세 범주를 기준으로 권한을 나눈다.

```text
Owner   → 파일 소유 사용자
Group   → 파일에 연결된 그룹
Others  → Owner도 아니고 Group에도 해당하지 않는 사용자
```

이 구조는 Day 3에서 배운 **User / Group / UID / GID** 개념과 연결된다.

### 실무에서 중요한 이유

운영 서버에서는 설정 파일, 로그, 인증 정보, 실행 스크립트마다 필요한 접근 수준이 다르다. 권한을 과도하게 부여하면 보안 사고나 설정 변조로 이어질 수 있으므로 **최소 권한 원칙**이 중요하다.

## 2. `ls -l`과 `ls -ld`

### `ls -l`

```bash
ls -l permission-test.txt
```

예시:

```text
-rw-r--r-- 1 linuxuser linuxuser 0 Sep 3 10:00 permission-test.txt
```

주요 필드:

```text
-rw-r--r--   → 파일 종류 + 권한
linuxuser    → Owner
linuxuser    → Group
```

### `ls -ld`

```bash
ls -ld /home/testuser
```

`-d`를 붙이면 `/home/testuser` 안의 파일 목록이 아니라 `/home/testuser` **디렉터리 자체의 정보**를 확인한다.

> 권한 문제를 확인할 때 파일은 `ls -l`, 디렉터리 자체는 `ls -ld`를 자주 사용한다.

---

## 3. 권한 문자열 구조

예:

```text
-rw-r--r--
```

구조:

```text
- | rw- | r-- | r--
  |     |     |
  |     |     └─ Others
  |     └─────── Group
  └───────────── Owner
```

맨 앞 한 글자는 권한이 아니라 **파일 종류**다.

| 문자 | 의미 |
|---|---|
| `-` | 일반 파일 |
| `d` | 디렉터리 |
| `l` | 심볼릭 링크 |

---

## 4. `r`, `w`, `x`

### 한 줄 정의

파일 기준으로 `r`은 읽기, `w`는 쓰기, `x`는 실행 권한이다.

| 권한 | 영어 | 파일에서의 의미 |
|---|---|---|
| `r` | read | 파일 내용 읽기 |
| `w` | write | 파일 내용 수정 |
| `x` | execute | 파일 실행 |

예:

```text
rw-
```

은 읽기와 쓰기는 가능하지만 실행은 허용되지 않는다는 뜻이다.

> `x` 권한을 준다고 일반 텍스트 파일이 자동으로 프로그램이 되는 것은 아니다. 실행 가능한 형식이나 스크립트여야 실제 실행 의미가 있다.

---

## 5. 숫자 권한 계산

Linux 권한은 다음 숫자를 조합해 표현할 수 있다.

```text
r = 4
w = 2
x = 1
```

예:

```text
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2     = 6
r-x = 4 + 1     = 5
r-- = 4         = 4
--- = 0         = 0
```

세 자리 숫자는 순서대로 다음을 의미한다.

```text
6 4 0
│ │ │
│ │ └─ Others
│ └─── Group
└───── Owner
```

### 자주 보는 권한

| 숫자 | 문자 권한 | 의미 |
|---|---|---|
| `600` | `rw-------` | Owner만 읽기/쓰기 |
| `640` | `rw-r-----` | Owner 읽기/쓰기, Group 읽기 |
| `644` | `rw-r--r--` | Owner 읽기/쓰기, 나머지 읽기 |
| `700` | `rwx------` | Owner만 모든 권한 |
| `750` | `rwxr-x---` | Owner 전체, Group 읽기/실행 |
| `755` | `rwxr-xr-x` | Owner 전체, 나머지 읽기/실행 |
| `777` | `rwxrwxrwx` | 모든 사용자에게 모든 기본 권한 |

## 6. `chmod`

### 한 줄 정의

`chmod`는 **change mode**의 의미로, 파일이나 디렉터리의 권한 비트를 변경하는 명령어다.

```bash
chmod 640 permission-test.txt
```

결과:

```text
Owner  → rw-
Group  → r--
Others → ---
```

`chmod`는 **누가 소유자인지를 변경하는 명령이 아니다.**

```text
chmod → 권한 변경
chown → 소유자 변경
```

`chown`은 다음 학습에서 다룬다.

## 7. 🧪 실습

### 실습 목표

파일을 만들고 숫자 권한을 직접 변경하면서 `ls -l` 출력이 어떻게 바뀌는지 확인한다.

### 1. 파일 생성

```bash
cd ~/linux-test
touch permission-test.txt
ls -l permission-test.txt
```

### 2. Owner만 읽기/쓰기

```bash
chmod 600 permission-test.txt
ls -l permission-test.txt
```

예상:

```text
-rw-------
```

### 3. Owner 읽기/쓰기, Group/Others 읽기

```bash
chmod 644 permission-test.txt
ls -l permission-test.txt
```

예상:

```text
-rw-r--r--
```

### 4. 실행 권한까지 포함

```bash
chmod 755 permission-test.txt
ls -l permission-test.txt
```

예상:

```text
-rwxr-xr-x
```

### 실습 문제 결과

```text
600 → rw-------
644 → rw-r--r--
700 → rwx------
755 → rwxr-xr-x

rw-r----- → 640
rwxr-x--- → 750
rw------- → 600
rwxr-xr-x → 755
```

Owner는 읽기/쓰기, Group은 읽기, Others는 권한 없음:

```bash
chmod 640 permission-test.txt
```

## 8. ⚠️ 헷갈리기 쉬운 부분

### `chmod`는 개인별로 권한을 하나씩 지정하는가?

정확히는 **Owner / Group / Others 세 범주**에 대해 권한을 지정한다.

즉 특정 사용자 여러 명을 각각 직접 지정하는 구조가 아니라, 파일의 소유자와 연결된 그룹을 기준으로 기본 권한을 적용한다.

### `644`면 아무도 접근할 수 없는가?

아니다.

```text
644
Owner  → rw-
Group  → r--
Others → r--
```

따라서 Group과 Others도 읽을 수 있다. **쓰기 권한이 없는 것**이다.

### `ls -l directory`와 `ls -ld directory`는 같은가?

아니다.

- `ls -l directory` → 디렉터리 내부 항목을 상세 출력
- `ls -ld directory` → 디렉터리 자체의 상세 정보 출력

## 9. 🔧 Troubleshooting

### 문제

중요한 서버 설정 파일 권한이 다음과 같았다.

```text
-rwxrwxrwx
```

즉 `777`이다.

요구사항은 Owner가 읽기/쓰기, Group과 Others는 읽기만 가능해야 한다.

### 원인

`777`은 Group과 Others에게도 쓰기 권한을 허용한다. 중요한 설정 파일을 일반 사용자가 수정할 수 있게 되면 설정 변조나 서비스 장애로 이어질 수 있다.

### 확인 방법

```bash
ls -l 설정파일명
```

### 해결

```bash
chmod 644 설정파일명
```

### 검증

```bash
ls -l 설정파일명
```

예상:

```text
-rw-r--r--
```

### 배운 점

권한은 넓게 주는 것이 편할 수 있지만 운영 서버에서는 **필요한 권한만 부여하는 것이 원칙**이다.

## 10. 💼 실무 포인트

권한 장애를 확인할 때는 단순히 `Permission denied` 메시지만 보고 바로 `chmod 777`을 적용하면 안 된다.

먼저 다음을 확인한다.

```bash
ls -l 대상파일
ls -ld 대상디렉터리
id
```

그리고 어떤 사용자/그룹이 어떤 작업을 해야 하는지 확인한 뒤 최소한의 권한만 조정한다.

```text
현재 권한 확인
→ Owner/Group 확인
→ 필요한 접근 수준 판단
→ 최소 권한으로 변경
→ 다시 검증
```

## 11. ✅ 핵심 정리

- Linux 기본 권한 대상은 **Owner / Group / Others**다.
- 파일 기준 `r` = 읽기, `w` = 쓰기, `x` = 실행이다.
- 숫자 권한은 `r=4`, `w=2`, `x=1`을 더해서 계산한다.
- `chmod`는 파일이나 디렉터리의 권한을 변경한다.
- `ls -l`은 파일 상세 정보, `ls -ld`는 디렉터리 자체 상세 정보 확인에 유용하다.
- `640` = `rw-r-----`, `644` = `rw-r--r--`, `755` = `rwxr-xr-x`다.
- `777`은 모든 사용자에게 쓰기까지 허용하므로 중요한 파일에서 함부로 사용하면 안 된다.
