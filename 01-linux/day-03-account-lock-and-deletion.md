## ⚡ 명령어 빠른 복습

| 명령어 | 용도 |
|---|---|
| `sudo passwd -l username` | 비밀번호 인증 잠금 |
| `sudo passwd -u username` | 비밀번호 인증 잠금 해제 |
| `sudo passwd -S username` | 비밀번호 상태 확인 |
| `id username` | 계정 존재 여부와 UID/GID 확인 |
| `ls -ld /home/username` | 홈 디렉터리 존재·소유권 확인 |
| `sudo userdel username` | 사용자 계정 정보 삭제 |
| `sudo userdel -r username` | 계정과 홈 디렉터리 등 사용자 데이터 함께 삭제 |

### `passwd` 주요 옵션

| 옵션 | 의미 |
|---|---|
| `-l` | **lock** - 비밀번호 인증 잠금 |
| `-u` | **unlock** - 비밀번호 인증 잠금 해제 |
| `-S` | **status** - 비밀번호 상태 출력 |

## 1. 계정 잠금이 필요한 이유

### 한 줄 정의

계정 잠금은 사용자를 바로 삭제하지 않고 **계정 정보와 데이터를 유지한 채 비밀번호 인증을 제한하는 조치**다.

### 상세 설명

운영 서버에서 퇴사자, 휴직자, 임시 차단 대상 계정을 바로 삭제하면 홈 디렉터리나 업무 파일을 확인하기 어려워질 수 있다.

따라서 상황에 따라 먼저 접근을 제한하고 데이터를 확인한 뒤 삭제하는 방식이 더 안전하다.

```text
확인
→ 잠금
→ 데이터 점검
→ 백업
→ 삭제 여부 결정
```

### 중요한 한계

`passwd -l`은 **비밀번호 인증 정보를 잠그는 것**이다. SSH 공개키 같은 다른 인증 수단이 별도로 허용되어 있다면 그것까지 자동으로 제거한다고 단정하면 안 된다.

즉 운영 환경에서는 로그인 경로 전체를 확인해야 한다.

## 2. `passwd -l`, `passwd -u`, `passwd -S`

### 계정 비밀번호 잠금

```bash
sudo passwd -l tempuser
```

`-l` = **lock**

계정 자체를 삭제하는 것이 아니라 `/etc/shadow`의 비밀번호 인증 상태를 잠그는 방식이다.

### 잠금 해제

```bash
sudo passwd -u tempuser
```

`-u` = **unlock**

잠겨 있는 비밀번호 인증을 다시 사용할 수 있는 상태로 되돌린다.

### 상태 확인

```bash
sudo passwd -S tempuser
```

`-S` = **Status**

예:

```text
tempuser L 2026-09-03 0 99999 7 -1
```

두 번째 필드는 비밀번호 상태를 나타낸다.

---

## 3. `passwd -S` 상태 값

| 상태 | 의미 |
|---|---|
| `P` | Password set - 사용 가능한 비밀번호가 설정된 상태 |
| `L` | Locked - 비밀번호 인증이 잠긴 상태 |
| `NP` | No Password - 비밀번호가 설정되지 않은 상태 |

뒤쪽 필드는 배포판과 도구 출력 형식에 따라 비밀번호 변경일, 최소/최대 사용 기간, 경고 기간, 비활성 기간 등의 정책 값을 보여준다.

현재 단계에서는 우선 `P`, `L`, `NP`를 정확히 구분하는 것이 핵심이다.

### `/etc/shadow`와의 연결

비밀번호 상태는 `/etc/passwd`가 아니라 주로 `/etc/shadow`의 인증 정보와 연결된다.

```text
/etc/passwd → 사용자 기본 정보
/etc/shadow → 비밀번호 해시와 비밀번호 정책 정보
```

## 4. `userdel`과 `userdel -r`

### `userdel username`

```bash
sudo userdel tempuser
```

사용자 계정 정보를 삭제한다.

기본 동작에서는 홈 디렉터리가 그대로 남을 수 있다.

```text
계정 삭제 O
/home/tempuser 삭제 X
```

### `userdel -r username`

```bash
sudo userdel -r tempuser
```

`-r`은 계정 삭제와 함께 홈 디렉터리와 메일 스풀 등 관련 사용자 데이터를 제거하도록 요청한다.

| 명령어 | 계정 | 홈 디렉터리 |
|---|---|---|
| `userdel username` | 삭제 | 남을 수 있음 |
| `userdel -r username` | 삭제 | 함께 제거 |

### 실무에서 중요한 이유

`-r`은 되돌리기 어려운 삭제 작업이다. 중요한 파일이 있는지 확인하지 않고 실행하면 업무 데이터를 잃을 수 있다.

또한 사용자의 파일이 반드시 홈 디렉터리 안에만 있는 것은 아니다. 홈 밖에 존재하는 소유 파일은 별도로 확인해야 할 수 있다.

---

## 5. 계정을 삭제했는데 `1001 1001`이 보이는 이유

### 한 줄 정의

Linux 파일 소유권은 사용자 이름이 아니라 **UID와 GID 숫자**를 저장한다.

예를 들어 계정이 존재할 때:

```text
linuxuser linuxuser
```

처럼 이름으로 보이지만, 해당 UID/GID와 연결된 계정 정보가 삭제되면:

```text
1001 1001
```

처럼 숫자가 그대로 표시될 수 있다.

### 동작 원리

```text
파일 메타데이터에 UID 1001 저장
        ↓
계정 존재
        ↓
시스템이 UID 1001 → tempuser로 이름 변환
```

계정 삭제 후:

```text
파일 메타데이터 UID 1001은 그대로 존재
        ↓
UID 1001과 연결된 사용자 이름 없음
        ↓
ls가 숫자 1001을 그대로 표시
```

### 실무에서 중요한 이유

남은 파일을 방치한 상태에서 미래에 같은 UID가 다른 계정에 재사용되면 소유권 관리가 복잡해질 수 있다. 따라서 계정 삭제 전후로 소유 파일을 확인하는 습관이 중요하다.

## 6. 🧪 실습

### 실습 목표

임시 계정을 생성하고 잠금/해제 상태를 확인한 뒤 계정만 삭제하여 홈 디렉터리가 남는지 확인한다.

### 1. 계정 생성

```bash
sudo adduser tempuser
id tempuser
ls -ld /home/tempuser
```

### 2. 계정 잠금

```bash
sudo passwd -l tempuser
sudo passwd -S tempuser
```

출력에서 `L`을 확인했다.

### 3. 잠금 해제

```bash
sudo passwd -u tempuser
sudo passwd -S tempuser
```

### 4. 계정만 삭제

```bash
sudo userdel tempuser
```

### 5. 삭제 결과 검증

```bash
id tempuser
ls -ld /home/tempuser
```

계정은 존재하지 않았지만 `/home/tempuser`는 남아 있는 것을 확인했다.

남은 홈 디렉터리의 소유자가 사용자 이름 대신 UID/GID 숫자로 표시되는 것도 확인했다.

## 7. ⚠️ 헷갈리기 쉬운 부분

### `userdel` 후 홈 디렉터리가 남아 있으면 삭제가 실패한 것인가?

아니다.

> ⚠️ 처음에는 홈 디렉터리가 남아 있으면 사용자 삭제가 실패한 것으로 생각할 수 있지만, 기본 `userdel`은 계정 정보와 홈 디렉터리를 별개로 처리한다.

계정 삭제 여부는 다음으로 따로 확인해야 한다.

```bash
id tempuser
```

### `passwd -l`은 계정을 완전히 비활성화하는가?

비밀번호 인증 잠금과 계정 자체 삭제는 다르다. 다른 인증 경로가 존재하는 운영 서버에서는 추가 점검이 필요하다.

### `userdel -r`이면 사용자가 만든 모든 파일이 사라지는가?

그렇게 단정하면 안 된다. 홈 밖의 파일이나 다른 저장 위치는 별도로 남을 수 있다.

## 8. 🔧 Troubleshooting

### 문제

```bash
sudo userdel tempuser
```

를 실행했는데 `/home/tempuser`가 그대로 남았다.

### 확인 방법

계정 존재 여부:

```bash
id tempuser
```

홈 디렉터리 존재 여부:

```bash
ls -ld /home/tempuser
```

### 원인

기본 `userdel`은 계정 정보를 삭제하지만 홈 디렉터리까지 제거하지 않는다.

### 해결 방법

처음부터 홈 디렉터리까지 삭제해야 하고 데이터 보존 문제가 없다면:

```bash
sudo userdel -r username
```

을 사용한다.

이미 계정만 삭제된 뒤 홈 디렉터리가 남았다면 해당 데이터가 정말 불필요한지 확인하고 별도로 정리한다.

### 배운 점

```text
계정 존재 여부
≠
홈 디렉터리 존재 여부
```

두 상태는 별도로 확인해야 한다.

## 9. 💼 실무 포인트

운영 환경의 계정 정리는 다음 흐름이 안전하다.

```text
1. 사용자 존재·UID/GID 확인
2. 필요 시 계정 잠금
3. 로그인 방식과 활성 세션 확인
4. 홈 디렉터리와 업무 데이터 확인
5. 필요한 데이터 백업
6. 사용자 소유 파일 확인
7. 계정 삭제
8. 잔여 파일과 디렉터리 확인
9. 최종 검증
```

삭제 명령보다 **삭제 전 확인 절차**가 더 중요하다.

## 10. ✅ 핵심 정리

- `passwd -l` → 비밀번호 인증 잠금
- `passwd -u` → 비밀번호 인증 잠금 해제
- `passwd -S` → 비밀번호 상태 확인
- `P` → 비밀번호 설정 상태
- `L` → 잠금 상태
- `NP` → 비밀번호 없음
- `userdel username` → 계정 삭제, 홈 디렉터리는 남을 수 있음
- `userdel -r username` → 계정과 홈 디렉터리 등 함께 삭제
- 계정 삭제 후 숫자 UID/GID가 보이는 이유는 파일 소유권이 숫자로 저장되기 때문이다.
